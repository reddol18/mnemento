# 작업 0002 — v0 2단계: 질문 파이프라인 + MCP 서버

- 지시: 지휘부 · 2026-10-03 · 선행: 0001 완료·지휘부 검수 통과
- 근거: PLAN 2-1(성공 지표), 5·5-1(Keeper 역할), ADR 0002·0004·0006·0008

## 만들 것

1. **질문 파이프라인** (`keeper/query/`) — PLAN 5-1 A
   - ① **해석**: 자연어 → `QuerySpec`(대상 스키마, 필터, 기간, 그룹, 집계, 비교). 관련 스키마의 **필드 설명·허용값만** 프롬프트에 넣는다(전체 데이터 금지). 구조화 출력으로 받고, 스키마에 없는 필드가 나오면 거부·재시도.
   - 모호하면 `Clarification`(선택지 목록)을 반환하고 실행하지 않는다.
   - ② **질의 정의**: `QuerySpec` → SQL(파라미터 바인딩, 생성 컬럼 사용). **코드로 변환**(LLM이 SQL을 직접 쓰지 않게) — 정확도·비용 양쪽에 유리.
   - ③ **답변 작성**: 집계 결과 + 근거(entity id 목록) + 한계(표본 수 < 5, 미완료 기간 등)를 자동 경고로 붙인다. LLM에는 **집계 결과만** 전달.
   - "오늘·어제·지난번" 같은 상대 표현은 설정 시간대로 해석하고 실제 범위를 답에 표시(ADR-0004).
   - 정형 질문(예: 특정 id 조회·단순 개수)은 LLM 없이 처리하는 빠른 경로.
2. **기록 도구** — 구조화 입력은 코드로 검증·저장, 자유 서술은 LLM이 구조화. 대상이 여럿이면 되묻기.
3. **동일 엔티티 판정 v0** (ADR-0006) — 외부 식별자 → 정규화 이름 + 별칭 사전. LLM 후보 제안은 되묻기만(자동 병합 금지).
4. **스키마 제안** (PLAN 5-1 B, 최소판) — 스키마에 없는 필드가 기록 요청에 반복되면 확장안을 `proposal`로 반환(자동 적용 금지).
5. **MCP 서버** — 도구: `record`, `query`, `get_entity`, `history`, `list_schemas`, `propose_schema`. Claude Code에 등록하는 방법을 README에 복사·붙여넣기 몇 줄로.
6. **측정 계측** — 질문마다 단계별 소요 시간, LLM 입력·출력 토큰을 기록(벤치마크 0003의 재료). LLM 호출은 어댑터로 감싸 모델 교체 가능하게.

## 하지 않을 것
- 실데이터 이관, 벤치마크 실행(0003), 의미 검색(v1)

## 완료 기준
- pytest 통과. 최소 포함: 해석 결과에 스키마 밖 필드 거부 / 모호 질문 → Clarification / QuerySpec→SQL 단위 테스트 / 표본 수 경고 / 정형 질문 LLM 미호출 / 별칭으로 동일 회사 판정
- **가상 데이터로 `docs/eval/questions.md` Q1~Q4 형태 질문이 실제로 답해지는 데모 로그** (질문·QuerySpec·SQL·답·근거·토큰·시간)
- Claude Code에 MCP로 등록해 실제 호출 1회 이상 확인
- 지휘부 보고: 테스트 수, 데모 로그 요약, 질문당 평균 토큰·시간, 설계와 달라진 점
