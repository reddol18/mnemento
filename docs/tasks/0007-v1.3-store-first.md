- 상태: **구현** (지휘부 지시 2026-10-04 — 보류함 방식 초안은 폐기하고 이 방식으로 대체)
- 근거: 사용자 질문 "플랫폼이나 속성이 추가돼도 저장·조회가 원활한가?"와 지적 "JSON이라 유연한데, 있는 레코드만 조회하면 되지 않나?"

## 이전 동작 (사실 확인, 실데이터 사본)
- enum 밖 값은 거부되고 관측조차 안 됨, 스키마 밖 필드는 거부(값 유실), 적용은 Python API로만, 예전 기록에 새 필드를 물으면 경고 없이 일부만 셈

## 만든 것
1. **저장** — 미등록 필드·enum 밖 값을 그대로 저장. 등록된 필드 위반(필수·타입·날짜)만 거부
2. **draft 사전** — 저장된 기록에서 계산(타입·견본·건수·처음 본 시각). `list_schemas`에 표시
3. **조회** — 해석기 사전에 draft를 "UNREGISTERED" 표시로 포함, 바로 질의 가능(`json_extract`), 쓰인 필드가 없는 기록 수 경고(항상)
4. **정리** — `propose_schema`(등록·라벨·인덱스·묶기 제안) → `apply_schema_proposal`(MCP, 사용자 동의 필수: approved_by + 답 기록, 설명·라벨 필수, 묶기는 `migrated` 이벤트로 이력 유지)
5. **비슷한 이름 확인 질문** — 저장은 하고 질문만, 자동 병합 금지
6. **실데이터** — 원본에서 지원자 수·열람 소요 시간을 다시 가져와 바로 저장·조회. 정식 등록은 사용자 승인 후
