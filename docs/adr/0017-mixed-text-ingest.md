# ADR-0017: 혼합 텍스트 수집(ingest) — 나누고, 분류하고, 근거와 함께 추출하고, 통째로 되돌릴 수 있게

- 상태: **승인** (작업 0008 ⑥⑦, 지휘부 2026-10-04)

## 맥락
LLM의 기억은 메모리 md 같은 텍스트에 있다. 한 파일 안에 여러 테이블로 나뉘어야 할 사실(지원 기록, 매매, 가격, 일정)과 저장할 대상이 아닌 지침·규칙·서술이 섞여 있다. dogfooding 가져오기는 원본마다 손으로 스크립트를 썼다(저장소 밖 로컬 스크립트). 이것을 일반 절차로 만들되, 지어낸 값 0건과 사용자 승인을 지켜야 한다.

## 결정 — 일곱 단계
1. **분할**: 문단·목록 항목·표 행 단위로 나눈다. 각 조각은 `(파일, 시작 줄, 끝 줄, 원문)`을 가진다.
2. **분류**: 각 조각을 다음 중 하나로 나눈다 — `existing:<type>`(기존 타입), `new_entity`(새 entity 후보), `new_series`(새 series 후보), `not_data`(규칙·지침·서술·메타). LLM이 분류하되 **스키마 사전과 조각 원문만** 본다. 확신이 낮으면 `ambiguous`.
3. **스키마 제안**: 새 타입 후보는 묶어서 `propose_schema`로 초안을 만든다(ADR-0016의 kind 판정 포함). 확정 전에는 추출하지 않는다.
4. **추출**: 각 사실을 기록 요청으로 바꾼다. 모든 값은 **조각 원문에 있는 문자열에서만** 온다 — 추출 결과마다 원문 근거(`source: 파일:줄범위`, `quote: 원문 일부`)를 붙이고, 코드가 `quote`가 실제 조각에 들어 있는지와 값이 `quote`에서 나왔는지(숫자·날짜 정규화 비교)를 검사한다. 근거가 맞지 않는 값은 버리고 "근거 불일치"로 보고한다. 날짜·시각 정밀도는 ADR-0013 규칙을 따른다.
5. **동일 엔티티**: ADR-0006대로 — 외부 식별자 → 정규화 이름·별칭. 후보만 있는 경우 자동 병합하지 않고 미리보기의 "애매" 목록에 올린다.
6. **미리보기(dry-run)**: 저장하지 않고 보고서를 만든다 — 조각별 분류, 제안 스키마(kind와 근거), 타입별 추출 기록 수, 형제 묶음, 새로 만들 참조 엔티티, 애매한 것(분류·동일 엔티티·근거 불일치·충돌), `not_data`로 둔 조각. MCP 도구 `ingest_preview(text|path)`.
7. **승인 후 일괄 반영**: `ingest_apply(preview_id, approved_by, user_answer)` — 미리보기와 같은 내용을 **하나의 ingest batch**로 쓴다. entity 쓰기는 정상 이벤트 경로(근거에 `ingest:<batch>` + 원문 위치), series 쓰기는 같은 batch 기록. `ingest_revert(batch_id)`가 그 batch의 entity 이벤트를 철회(`retracted`, 원래 기록은 남음)하고 series 점을 되돌린다.

## 조각과 기록의 대응 — 1조각 N기록, N조각 1기록, 충돌
### 근거 span
- 조각 하나는 **span** 하나다: `span_id = 해시(원본 식별자, 시작 줄, 끝 줄, 원문)`. 추출한 기록의 이벤트 근거(evidence)에 `span:<id>`와 `quote`를 넣는다. 원본 식별자는 batch 안의 상대 이름이고, 절대 경로는 로컬 batch 기록에만 둔다.
- 열린 문제(⑥ 구현 때 결정): span_id에 원문 해시가 들어가므로 원본 파일이 바뀌면 같은 사실이라도 span이 달라진다. 재수집 때 "같은 위치, 원문 변경"을 감지해 근거 갱신으로 처리할지, 새 span으로 둘지 정한다.

### 한 조각에서 여러 기록이 나올 때
예(가상): "7/30 가상바이오 모의 1회차 12,340원 매수 — 수출 반등이 근거" → **체결** 기록 + **판단** 기록. 둘 다 종목(회사) 엔티티를 참조한다.
- **a. 다른 엔티티를 가리키는 값은 참조(ref)로 잇는다.** 종목명을 두 기록에 복사하지 않는다. 엔티티가 없으면 ADR-0006대로 처리한다. 외부 식별자(종목 코드)가 있으면 미리보기에 "새 엔티티 생성"으로 올리고, 없거나 이름만 비슷하면 애매 목록에 올려 묻는다.
- **b. 두 기록 모두의 고유 속성은 각 기록에 중복 저장한다**(날짜·가격 등). 체결의 가격과 판단 시점의 가격은 각 기록의 사실이므로 중복은 정상이다.
- **c. 같은 span에서 나온 기록은 형제(sibling)다.** 같은 `span_id`로 묶이고, `get_entity`·`history`에 형제 목록이 나온다.

### 형제 기록의 정합성 — 알리되 자동으로 고치지 않는다
- 공유값은 같은 span에서 같은 원문 값으로 추출된 값이다. 이 값을 한 기록에서 정정(`corrected`)하면 **형제 기록에 같은 값이 있다는 경고**를 돌려주고, 함께 정정할지 묻는다(`record` 응답의 `questions`).
- 형제 기록은 사용자가 답한 뒤에만 고친다. **자동 전파는 하지 않는다.** 판단 시점 가격처럼 "같은 숫자지만 다른 사실"일 수 있기 때문이다.
- 철회(`retracted`)도 같다. 형제 목록을 알리고, 함께 철회할지 묻는다.
- `ingest_revert`(batch 전체 되돌리기)는 batch 안의 형제를 모두 함께 되돌린다. 승인 단위가 batch이기 때문이다.

### 이중 집계 방지
- 같은 사건이 두 타입에 있어도 **질의는 대상 타입 하나에서 센다.** QuerySpec의 source는 타입 하나이고, 타입을 합쳐 세는 질의는 만들지 않는다.
- 스키마에 **관계 설명**을 둔다: `relations: [{type: "trade_decision", note: "체결과 판단은 같은 사건의 다른 측면일 수 있다 — 매수 횟수는 체결에서 센다"}]`. 해석기 사전에 이 문장이 보이게 해서 "몇 번 샀나"를 체결에서 세도록 돕는다.
- 이 설명은 사전 문장일 뿐이다. 실행은 계속 타입 하나에서 하고, 조인이 생기지 않는다.

### 여러 조각에 같은 사실이 반복될 때
- 여러 파일이나 문단에 같은 사실이 나오면 **기록 하나로 묶고, 근거 span을 여러 개** 둔다(이벤트 근거에 span 목록).
- 같은 사실인지는 ADR-0006 identity로 판단한다. 같은 대상(외부 식별자 또는 정규화 이름)이고 같은 시점·종류인지 본다.
- 값이 모두 같으면 묶는다. **값이 하나라도 다르면 충돌**로 미리보기의 애매 목록에 올리고, 어느 쪽인지 사용자에게 묻는다. 자동으로 고르지 않는다(최신 파일 우선 같은 규칙도 두지 않음).
- 이미 장부에 있는 사실과 같으면 새 기록을 만들지 않고 근거 span만 덧붙인다. 다르면 충돌로 보고한다(ADR-0014의 "현재 상태와 모순" clarify와 같은 처리).

## `not_data` 조각
- 저장하지 않지만 버리지도 않는다: `ingest_notes(batch, source, 줄범위, 요약 한 줄)`로 **원문 참조만** 남긴다(원문 복사 없음). "이 지침은 어디 있었나"를 찾을 수 있게 하되 장부의 사실과 섞지 않는다.

## 평가
- 정답 라벨셋: 조각별 분류, 기대 기록(타입·필드·값), kind. **공개 저장소에는 가상 텍스트로 만든 라벨셋만** 둔다(메모리 md 흉내: 지원 기록·매매·가격 표·지침이 섞인 가상 파일 여러 개).
- 실데이터 평가는 로컬에서만 하고, 경로·결과 원문을 저장소에 남기지 않는다(숫자 요약만 보고).
- 라벨셋에는 세 경우를 모두 넣고 정답을 둔다. **1조각→N기록**(정답: 기록 목록 + 형제 묶음 + ref 대상), **N조각→1기록**(정답: 기록 하나 + span 목록), **충돌**(정답: 충돌로 보고되어야 할 필드).
- 지표: 분류 정확도, 추출 정밀도·재현율(필드 단위), **원문에 없는 값 0건**(근거 검사로 강제), kind 판정 정확도, 동일 엔티티 오병합 0건, 형제 묶음 정확도, ref 연결 정확도, 충돌 탐지 재현율(놓친 충돌 0건 목표).

## 대안
| 대안 | 기각 이유 |
|---|---|
| LLM이 한 번에 JSON으로 전부 추출 | 근거 검사가 안 되고, 지어낸 값이 섞여도 모른다 |
| 원본마다 수작업 스크립트 | dogfooding에서 해 봤다 — 정확하지만 확장되지 않는다 |
| 미리보기 없이 바로 저장 + 나중에 철회 | 잘못 들어간 뒤 정리하는 비용이 크고 질의 결과가 흔들린다 |

## 결과
- 텍스트 기억을 장부로 옮기는 일이 "미리보기 → 승인 → 한 batch"가 되어, 되돌릴 수 있고 근거가 남는다. 비용은 LLM 분류·추출 호출(조각 수에 비례) — 미리보기에 예상 호출 수를 표시한다.
