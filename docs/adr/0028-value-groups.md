# ADR-0028: 값 묶음 — 한 표현이 enum 값 여러 개를 뜻할 때

- 상태: **승인** (이슈 https://github.com/reddol18/mnemento/issues/9, 사용자 지시로 처리 2026-10-12)

## 맥락
실사용에서 "지금 주시 중인 종목"을 한 필드로만 읽어서, 상태가 `watching`인 것과 `observe_only`(관찰 전용)인 것 중 일부가 빠졌다. 사용자의 말로 "주시 중"은 두 상태를 모두 뜻한다. 라벨(ADR-0004 이후의 `labels`)은 값 하나에 낱말 여러 개를 붙일 뿐이고, 낱말 하나에 값 여러 개를 붙이지는 못했다.

## 결정
1. **스키마 필드 `value_groups`**: `{표현: [값, …]}` 형태로 둔다. enum 필드에만 쓰고, 값은 허용값 중 두 개 이상이어야 한다. 기존 값을 바꾸지 않으므로 추가형 변경이다(ADR-0005).
2. **해석기**: 사전에 "phrase groups (op in with all of them): '주시 중' = watching, observe_only"로 보인다. 규칙은 "묶음 표현은 그 값 전부를 `in`으로 거른다"이다.
3. **사용자 DB에는 동의를 받고만 넣는다.**
   - `add_value_group(entity_type, field, phrase, values, approved_by, user_answer)`(Keeper·MCP)를 쓴다. 새 스키마 버전으로 등록하고, 승인 기록에 남긴다.
   - 저장소 스키마 파일에 들어 있는 묶음은 정리된 DB에 ADR-0023의 항목별 제안(`group:<필드>=<표현>`)으로 간다. DB에 없는 표현은 기본 적용 대상이고, 이미 있는 표현을 바꾸는 것은 골라야 적용된다.

## 대안
| 대안 | 기각 이유 |
|---|---|
| 라벨에 같은 낱말을 두 값에 붙이기 | 해석기가 둘 중 하나만 고르는 일이 그대로 남는다. 라벨은 값 하나를 가리키는 말이다 |
| 해석기 규칙에 도메인 문장으로 적기 | 사용자·도메인마다 다른 말이라 코드에 넣을 수 없다 |

## 결과
- "주시 중" 같은 사용자의 말이 사전의 일부가 된다. 실DB에 넣을지는 사용자가 정한다.
