# ADR-0002: 단일 기록 창구 — Keeper 에이전트

- 상태: 채택 · 2026-10-02

## 맥락
여러 에이전트가 각자 파일·DB에 직접 쓰면 형식이 흩어지고, 같은 대상(회사·공고)이 다른 이름으로 중복 저장된다. 실제로 지원 기록이 메모리 파일·HTML 속 JSON·아티팩트 localStorage로 나뉘어 개수를 잘못 셌다.

## 결정
- 저장소를 만지는 존재는 **Keeper 하나**다. 다른 에이전트는 Keeper에게 **대화(자연어) 또는 구조화 메시지**로 요청한다.
- 핵심 기능은 **MCP 서버**로 구현하고, 대화형 창구(세션 간 메시지)는 그 위의 얇은 층으로 둔다.
- 쓰기 경로 분리: 스키마에 맞는 구조화 입력은 **코드로 즉시 검증·저장**, 자유 서술만 LLM이 구조화.
- 불확실한 입력(대상 엔티티가 여럿, 필수 필드 누락)은 **저장하지 않고 되묻는다.**

## 결과
- 정규화·동일 엔티티 판정·근거 기록을 한곳에서 강제할 수 있다.
- Keeper가 병목이 될 수 있으나 개인 규모에선 무의미.
