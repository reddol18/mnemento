# ADR-0004: 시간 표기 — 시각은 오프셋 포함 ISO 8601, 날짜는 사용자 시간대 기준

- 상태: 채택 · 2026-10-02

## 맥락
"오늘 지원 몇 곳?"의 "오늘"은 사용자의 달력 기준이다. 반면 이벤트 순서와 경과 시간("2주째 결과 없음")은 정확한 시각이 필요하다. UTC로만 저장하면 한국 시간 새벽 기록이 전날로 집계되는 오류가 생긴다.

## 결정
1. **시각(instant)** — 이벤트의 `at`, `recorded_at`은 **오프셋 포함 ISO 8601**(`2026-10-02T17:40:00+09:00`)로 저장. 비교·정렬은 UTC로 환산해서 한다.
2. **날짜(calendar date)** — `applied_at`처럼 "그날"이 의미인 필드는 **`YYYY-MM-DD`**, 사용자 설정 시간대(기본 `Asia/Seoul`) 기준.
3. **상대 표현 해석** — "오늘·어제·이번 주"는 Keeper가 **설정 시간대**로 날짜 범위로 바꾼 뒤 질의한다. 해석 결과(실제 날짜 범위)를 답에 함께 표시한다.
4. 스키마 사전에서 필드마다 `format: date-time | date`를 명시해 LLM이 혼동하지 않게 한다.

## 결과
- "이벤트가 실제로 일어난 시각"(`at`)과 "기록된 시각"(`recorded_at`)을 구분해 둔다 — 지원 다음 날 기록해도 지원일이 틀어지지 않는다.
