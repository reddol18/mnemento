# ADR-0005: 스키마 진화 — 문서마다 스키마 버전, 추가는 자유·파괴적 변경은 이벤트로 이행

- 상태: 채택 · 2026-10-02

## 맥락
기록 종류는 쓰면서 바뀐다(예: 지원 기록에 "AI 서류 합격률" 필드가 나중에 생김). 문서 DB의 유연함을 살리면서도, 스키마 사전과 실제 데이터가 어긋나면 LLM 질의가 틀린다.

## 결정
1. 스키마는 `name` + **정수 버전**으로 관리하고, 모든 entity에 `schema_version`을 기록한다.
2. **추가형 변경**(선택 필드 추가, 허용값 추가) — 버전만 올리고 기존 문서는 그대로 둔다. 질의 시 없는 필드는 `null`로 취급.
3. **파괴형 변경**(필드 이름 변경·삭제, 타입 변경, 허용값 축소) — **이행 스크립트**가 대상 문서마다 `migrated` 이벤트를 남기며 변환한다. 원본은 이벤트 기록에 그대로 남는다.
4. 스키마 사전 자체의 변경도 이력으로 보관한다(어느 시점에 어떤 필드가 있었는지 답할 수 있게).

## 결과
- 오래된 문서와 새 문서가 섞여도 질의 의미가 유지된다.
- 파괴형 변경은 의도적으로 번거롭게 만들어 남발을 막는다.
