# ADR-0011: 벤치마크 하네스 — 같은 사실·같은 CLI·같은 답변 스키마, 정답은 생성기 원본에서

- 상태: 채택 · 2026-10-03
- 근거: ADR-0008(방법론), 지휘부 0003 지시(과적합 방지, CLI 어댑터 확정, B1은 Claude Code 메모리 재현)

## 결정
1. **데이터** — `bench/generate.py`가 시드로 가상 구직 기록을 만든다(규모 100 / 1,000 / 10,000, 기준 시각 2026-11-20 — 개발 데모와 다르게). 상태 비율, 열람 지연(로그정규), 정정 약 2%, 중복 기록 철회 약 1%, 영문 별칭 회사 약 30%, 서치펌 사유 패스 약 4%. 실명 없음.
2. **같은 사실, 세 가지 형태** — `bench/render.py`
   - M: 정상 기록 API(`record_event`)로 Mnemento 장부 생성 — 정정·철회도 이벤트로
   - B1: Claude Code 메모리 형식 — `MEMORY.md` 색인(한 줄 = 파일 하나) + 기록마다 frontmatter 있는 md 파일. 정정·철회는 파일 본문에 적는다. 색인은 **앞 200줄만** 프롬프트에 넣는다(Claude Code 동작과 같게)
   - B0: B1의 md 파일 전부를 이어 붙여 프롬프트에 넣는다
3. **정답은 생성기 원본에서** — `bench/questions.py`가 Python 객체에서 직접 계산한다. Mnemento 코드를 거치지 않으므로 Mnemento의 버그가 자기 정답을 맞게 보이게 만들 수 없다. 대신 테스트가 "손으로 쓴 정답 QuerySpec → Mnemento → 채점"이 모든 문항에서 통과하는지 확인해, 생성기·렌더러·채점기 사이의 불일치를 잡는다.
4. **문항 두 묶음** — dev(D1~D7, docs/eval Q1~Q7 형태, 개발 중 사용)와 unseen(U1~U8, 표현 변경과 새 문항). 측정 전에 고정하고, 측정 중에는 프롬프트·규칙·문항을 고치지 않는다(`FROZEN_FILES` 해시를 run마다 기록, 바뀌면 같은 run을 이어서 돌릴 수 없음).
5. **같은 답변 스키마 + 형식 힌트** — 모든 비교군은 `number / ids / groups / flags / text` 객체로 답한다. 문항마다 짧은 형식 힌트(무엇을 number에, groups의 value가 무엇인지)를 모두에게 똑같이 준다. 채점은 기계적이다: 숫자(허용 오차·대안 해석 명시), id 집합(정답 50개 이하일 때), 그룹 값(±0.02), 플래그.
6. **M의 답 변환** — M은 구조화 결과를 코드로 같은 스키마에 옮긴다(LLM 없이). 해석에는 형식 힌트를 주지 않고 질문만 준다.
7. **같은 CLI·같은 모델** — 모든 비교군이 `ClaudeCLIAdapter`(같은 플래그, 설정 파일·MCP 없음)를 쓴다. B1만 Read/Grep/Glob를 허용하고 메모리 폴더에서 실행한다. 고정 오버헤드(도구 없음 2,526 / 도구 있음 6,698 입력 토큰, 약 2초)는 `calibrate`로 재서, 표에 포함 값과 제외 값을 둘 다 싣는다. 시간은 ① CLI 프로세스(벽시계 − API 시간) ② 모델(API 시간) ③ 코드로 나눈다.
8. **캐시가 비어 있는 상태로 측정** — M은 반복마다 DB 사본을 새로 써서 QuerySpec 캐시가 비어 있다. 캐시 효과는 따로 보고한다(같은 패턴을 다시 물으면 LLM 0회).
9. **측정 불가도 결과** — B0의 입력이 컨텍스트(200k)를 넘으면 호출하지 않고 "측정 불가(컨텍스트 초과)"로 기록한다.

## 대안
| 대안 | 기각 이유 |
|---|---|
| 정답을 Mnemento로 계산 | 순환 — 버그가 정답에 섞인다 |
| 자유 서술 답변을 LLM으로 채점 | 채점자 편향·비용. 형식 힌트 + 기계 채점이 재현 가능 |
| M을 Claude Code 에이전트 + MCP 도구로 측정 | 에이전트 루프 호출이 하나 더 붙어 파이프라인 자체 비교가 흐려진다. 별도 변형으로 추후 측정 가능 |

## 한계
- unseen 문항(U1~U8)은 구현자가 썼다 → 지휘부가 독립적으로 쓴 문항 5개(H1~H5)를 추가했다.
- 지휘부 문항 5개도 생성기 스키마를 안 상태에서 썼다.
- H3(같은 회사 2회 이상)는 변별력이 낮다: 생성기상 회사당 평균 약 3건이라 대부분의 회사가 해당하고, 생성 데이터에는 같은 회사가 다른 이름으로 중복 기록된 경우가 없어 별칭 묶기 검증이 약하다. M의 기능 공백을 안 뒤라 교체하지 않았다(결과 선택 방지).
- QuerySpec v0로 표현할 수 없는 문항이 있다: H3(그룹 크기 조건, HAVING), H4(이벤트 시각 정렬). v0는 고정된 상태로 측정해 지는 결과까지 싣고, 확장 후 재측정은 "v1"로 따로 표시한다(v0 결과를 덮어쓰지 않음).
- 형식 힌트가 B0/B1에 구조를 알려 주므로, 실사용(힌트 없음)보다 B0/B1에 유리할 수 있다.
- CLI 프롬프트 캐시(5분)가 B0의 반복 호출 비용을 크게 낮춘다 — 캐시 읽기 토큰을 따로 표시한다.
