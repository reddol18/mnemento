# ADR-0012: "도달 여부"는 이벤트 이력으로 — QuerySpec `reached` 필터

- 상태: 채택 · 2026-10-03 (지휘부 0004 검수)

## 맥락
v0 측정에서 "열람된 지원"을 현재 status(`viewed`, `passed`)로 해석해, 열람된 뒤 불합격된 건을 빠뜨렸다(H2). "~된 적 있음 / ~까지 간"은 현재 상태가 아니라 **이력**에 대한 질문이다.

## 결정
- QuerySpec 필터에 `op: reached`(status 필드 전용)를 추가한다. 레코드가 그 상태에 **한 번이라도** 도달했으면 참이다.
- 판단 근거는 **정정·철회를 반영해 재생한 이벤트 이력**이다(ADR-0003·0007·0009). 재생할 때 도달한 상태 목록을 현재 상태와 함께 파생 데이터로 저장한다(언제든 재생성 가능).
- 스키마 사전의 status 필드에 단계 함의(`implies`, 예: `passed`는 `viewed`를 거친 것)를 적어 두고, 해석 프롬프트에서 "도달 여부는 reached, 현재 상태는 eq"를 구분하게 한다.

## 대안
- (a) 날짜 필드(`viewed_at`) 존재 여부로 판단 — 날짜가 비어 있거나 정정된 경우 틀린다. 정본(이벤트)과 어긋날 수 있어 기각.
