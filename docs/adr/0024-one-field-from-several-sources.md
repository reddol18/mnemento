# ADR-0024: 한 필드를 원본 여러 곳에서 가져올 때

- 상태: **승인** (이슈 https://github.com/reddol18/mnemento/issues/8, 사용자 지시로 처리 2026-10-07)

## 맥락
실사용 비교에서 "관찰 전용 종목" 질문에 4종 중 3종만 답했다. 원본 프로젝트가 같은 표시를 설정 파일 두 곳에 따로 두는데, 가져오기는 한 곳만 읽었다. 빠진 1종은 첫 파일에 아예 없는 종목이었다. 원본 쪽의 이중 관리를 고치는 일은 Mnemento의 범위가 아니다. 대신 Mnemento는 그런 원본을 받아들이면서, 답이 어느 정도 근거 위에 있는지 말해야 한다.

## 결정
1. **`mnemento.importer.combine`**: 한 필드의 값을 원본별로 받아(`{원본: 값 또는 None}`) 저장할 값을 정한다.
   - `first`: 주어진 순서에서 처음으로 값이 있는 원본
   - `any`: 하나라도 참이면 참(표시·플래그)
   - `union`: 목록의 합집합
2. **불일치를 보고한다.** 일부 원본에 값이 없거나 원본끼리 값이 다르면 다음과 같이 처리한다.
   - 가져오기 보고(`ImportReport.mismatches`)에 기록·필드·원본별 값을 남긴다
   - DB의 `source_coverage`(기록, 필드, 원본 수, 값이 있는 원본 수, 상세)에 저장한다
   - 다음 가져오기에서 모두 일치하면 그 기록을 지운다(멱등)
3. **답에 경고를 붙인다.** 질문이 그 필드를 쓰면(필터·그룹·측정) 이렇게 알린다: "그 종류의 기록 N건은 이 필드를 원본 일부에서만 가져왔거나 원본끼리 어긋난다(최소 M/N곳). 가져오기 보고 참조". 필드를 쓰지 않는 질문에는 붙이지 않는다.

## 근거
- 합집합으로 넣으면 빠뜨리는 쪽(재현율)의 실패를 막는다. 원본이 어긋난다는 사실은 경고로 드러나므로, 지어낸 정확함이 생기지 않는다.
- 불일치를 문서(doc) 안에 넣지 않고 별도 표에 둔다. 그래서 기록 내용과 스키마가 오염되지 않고, 어느 종류의 기록에도 쓸 수 있다.

## 대안
| 대안 | 기각 이유 |
|---|---|
| 원본 하나를 정본으로 정하고 나머지는 무시 | 지금의 실패 그대로(4종 중 3종) |
| 불일치를 기록마다 doc 필드로 저장 | 스키마에 없는 필드가 draft로 퍼지고, 질문 해석에 섞인다 |
| 원본이 어긋나면 가져오기를 멈춤 | 원본은 매일 바뀌는 사본이다. 멈추면 나머지 갱신까지 막힌다 |

## 결과
- 실데이터 가져오기 스크립트(저장소 밖)는 보조 원본을 읽어 이 함수로 합친다. 실DB 반영은 사용자 승인 후에 한다.
