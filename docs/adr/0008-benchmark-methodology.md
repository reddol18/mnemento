# ADR-0008: 벤치마크 방법론 — 정확도·속도·비용을 LLM 자체 메모리와 실측 비교

- 상태: 채택 · 2026-10-03

## 맥락
Mnemento의 존재 이유는 "LLM이 자기 메모리(컨텍스트·메모 파일)만 쓸 때보다 낫다"는 것이다. 주장만으로는 포트폴리오 가치가 없고, 같은 조건에서 잰 숫자가 있어야 한다.

## 결정
1. **비교군**: B0 전체 컨텍스트 / B1 마크다운 메모리+파일 검색 / B2 벡터 메모리(가능 시) / M Mnemento.
2. **고정 조건**: 같은 모델·같은 온도·같은 문항·같은 데이터. 각 문항 최소 5회 반복.
3. **정확도**: 문항별 정답 대비 채점. 숫자·목록이 맞는지 + 근거 제시 여부 + 필요한 경고(표본 수 등) 포함 여부. 채점 기준은 문항 파일에 미리 고정(사후 조정 금지).
4. **속도**: 질문 입력부터 최종 답변까지 벽시계 시간. 평균과 p95. 도구 호출·DB 질의 시간 포함.
5. **비용**: 질문당 입력·출력 토큰(캐시 토큰 별도 표기)과 금액. 모델 단가는 측정일 공식 가격표 기준으로 표기.
6. **데이터 규모별 곡선**: 기록 100 / 1,000 / 10,000건에서 반복 — 규모가 커질수록 B0·B1 비용이 늘고 M은 거의 일정하다는 가설을 검증.
7. **재현성**: 벤치마크 스크립트·가상 데이터·문항·원자료 결과(JSON)를 저장소에 포함. README 표는 이 결과에서 자동 생성.
8. **불리한 결과도 공개**: M이 지는 항목(예: 소규모에서 B0보다 느림)은 그대로 표기하고 이유를 적는다.

## 결과
- 공개 저장소에는 가상 데이터 벤치마크만 싣는다. 실데이터 결과는 내부 참고용(`data/private/`).
