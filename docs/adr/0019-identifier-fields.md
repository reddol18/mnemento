# ADR-0019: 외부 식별자 필드로 먼저 찾기

- 상태: **제안** (작업 0008 ③b, 지휘부 검수 대기) · 2026-10-04

## 맥락
③a 실데이터 질문에서 "바이오주(900001)", "샘플펀드(900002)"처럼 별칭과 코드가 함께 나왔다. 해석기는 별칭만 `name_is`에 넣었고, 이름 해석은 정확한 이름이나 별칭으로만 찾아서 연결하지 못했다(되묻기 또는 일치 없음). ADR-0006은 "외부 식별자 → 정규화 이름·별칭" 순서를 정했지만, 외부 식별자는 사업자번호 하나로 고정돼 있었다.

## 결정
1. 스키마 필드에 `identifier: true`를 둔다(자유 문자열 필드만). 종목 코드, 펀드 표준코드, 사업자번호처럼 같은 값이면 같은 대상인 필드다.
2. 이름 해석 ①단계: 질문 텍스트에서 식별자처럼 생긴 토큰(영문·숫자, 하이픈 무시, 4자 이상)을 뽑는다. 그 토큰이 식별자 필드 값과 같으면 확실한 일치로 본다(규칙 이름 `identifier:<field>`). 날짜 조각("10/2")과 짧은 숫자는 토큰이 아니다.
3. 해석기 규칙: `name_is` 값에는 질문에 쓰인 그대로 코드·번호를 포함해 넣는다.
4. ②단계(정규화 이름·별칭)와 약한 신호(후보만 제시, 자동 연결 없음)는 그대로다.
5. 식별자 표시가 없는 스키마는 v0 규칙(10자리 사업자번호)을 유지한다. 저장소의 company 스키마는 business_number에 표시를 달아 v2가 된다.

## 대안
| 대안 | 기각 이유 |
|---|---|
| 해석기가 코드를 별도 필터로 쓰게 하기 | 코드 필드는 참조 대상(security) 쪽에 있어서 trade·decision 필터로 바로 쓸 수 없다. 이름 해석이 맡는 편이 일반적이다 |
| 별칭 사전에 코드를 넣기 | 코드는 별칭이 아니라 식별자다. 별칭은 사람이 승인해 늘리는 것이다 |

## 결과
- 투자(종목 코드)와 구직(사업자번호)에 같은 규칙이 적용된다.
- 6자리 숫자 코드와 날짜 조각("202609")이 우연히 같을 수 있다. 토큰을 4자 이상으로 제한해 위험은 작지만, 0은 아니다.
